# Подключение фронтенда к Django на сервере

Фронтенд обращается к API по относительным адресам `/api/...`. В локальной разработке запросы перенаправляет Vite, а на сервере их должен маршрутизировать Caddy.

## Что делает конфигурация

- `:80`: API, Django Admin и статика Django отправляются в контейнер `backend:8000`; все остальные запросы идут во `frontend-prod:80`.
- `:8080`: те же пути отправляются в `backend:8000`; остальные запросы идут во `frontend-stage:80`.
- Caddy подключается к обычной сети фронтенда и к общей Docker-сети `quest_backend`.

## Требования к бэкенду

В `docker-compose.yml` отдельного репозитория бэкенда сервис `backend` должен быть подключён к внешней сети с именем `quest_backend`. См. патч `backend-shared-network-patch.zip` или раздел в документации бэкенда.

## Первоначальный запуск

1. Убедитесь, что серверный `.env` бэкенда настроен для публичного адреса. Для текущего HTTP-стейджинга пример значений:

   ```dotenv
   DJANGO_DEBUG=0
   DJANGO_ALLOWED_HOSTS=168.113.158.11,localhost,127.0.0.1,backend
   DJANGO_CSRF_TRUSTED_ORIGINS=http://168.113.158.11,http://168.113.158.11:8080
   ```

   Если IP/домен или протокол изменится, обновите эти значения. Секретный ключ и пароль БД должны быть собственными случайными значениями и не должны попадать в Git.
2. Создайте общую сеть один раз (скрипт деплоя фронтенда также создаёт её автоматически):

   ```sh
   docker network inspect quest_backend >/dev/null 2>&1 || docker network create quest_backend
   ```

3. Поднимите Compose-проект бэкенда из его репозитория.
4. Обновите файлы `deploy/Caddyfile`, `deploy/docker-compose.yml` и `deploy/deploy.sh` в репозитории фронтенда.
5. Выполните деплой фронтенда. Скрипт проверит Caddyfile и применит его через `caddy reload`.

## Проверка

На стейджинге проверьте:

```sh
curl -i http://127.0.0.1:8080/api/health/
curl -i http://127.0.0.1:8080/api/quest-config/
curl -I http://127.0.0.1:8080/admin/
```

`/api/health/` должен вернуть успешный JSON-ответ. `/api/quest-config/` должен вернуть публичную конфигурацию выбранного квеста. `/admin/` должен вести в Django Admin (без авторизации будет страница входа).

## Безопасность

Порт Django не требуется публиковать во внешнюю сеть: Caddy обращается к `backend:8000` внутри Docker-сети. В Compose бэкенда можно привязать порт 8000 к `127.0.0.1` для локальной диагностики, а внешним клиентам оставить только порты Caddy.
